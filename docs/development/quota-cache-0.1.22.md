# 0.1.22 账户刷新保留有效快照

## 问题与行为

面板隐藏一段时间后重新打开，可能显示“账户待连接”和“尚未获得有效额度快照”。文件监听此前把 auth.json、config.toml 或 .env 的变更通知直接当成换号：先清空身份、额度、余额、重置卡和账户资料，再等待后台核验；同账户凭据续期也会丢失有效快照。认证暂时失败还会提前清空部分账户信息。

本轮将文件通知视为核验线索。收集器合并同来源通知，在锁外执行有限大小的本地 probe；未变化不失效，同账户续期保留上次成功值，确认不同或未知账户才清空。忽略读访问通知，保留写入关闭、修改、创建、删除及通用通知，避免自身读文件反复触发失效。WSL 仍沿用原有后台 probe，不在收集器启动 WSL。

刷新中的额度卡显示“正在刷新 · 显示上次成功数据”；临时失败沿用已过期提示，保留最后有效值与成功时间。新请求成功后统一替换。真实换号、退出登录、无法核验身份或来源配置变化仍清除旧账户数据；启动持久化缓存仍先核验身份再投影，前端不另建缓存。

账户启动 / 面板可见性 / 手动模式策略、请求合并、Resets 固定调度和本地日志采集保持原样。凭据变化不能缩短已有服务端或网络等待；本地过期再续期也保留等待的原始原因，不误当成认证退避解除。
