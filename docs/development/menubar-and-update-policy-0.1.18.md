# 0.1.18 菜单栏状态与更新检查

## 行为

macOS 菜单栏保留模板 SF Symbol，使用 AppKit 原生 13 pt 等宽数字字体，显示工作状态、当前模型和轮次平均输出速度，例如 `忙 · 6.1-sol · 38.4 t/s`。多个运行会话显示数量，长模型名省略。重要未读重置公告 / 计划显示 `↻`，普通动态显示 `•`，来源异常显示 `!`；悬停和 VoiceOver 提供详细说明，不输出会话标题、路径或原始错误正文。

运行判断与 Windows 小浮窗一致：active、来源 connected、最近五分钟内有活动；否则未知或空闲。未完成的速度样本超过一分钟显示 `—`；没有运行会话时清空模型及速度。使用已有采集循环最多每秒计算一次，缓存相同结果、合并待执行 AppKit 写入；只修改文字 / tooltip，不替换 template 图像。隐藏或销毁 WebView 不停止更新，无新增网络任务。

更新检查由 Rust 启动流程执行一次，不依赖首次显示面板。此后只有手动点击检查才请求。独立 `get_app_update_info` IPC 只读取进程内缓存；前端挂载、显示和重建只读状态，原有周期检查 effect 已删除。失败不安排自动重试；启动标记在首次尝试时消耗，手动检查若先完成也不会再被启动检查重复执行。

保留服务锁单飞、至少 60 秒间隔、失败退避 / Retry-After、进度 revision，以及签名下载和点击后安装。下载 / 待安装 / 安装阶段不会重复查询或下载。`next_check_at` 表示可手动重试的最早时间，不再驱动定时器。账户可见性调度、Resets 固定刷新、本地日志、Tokens 和 token/s 均独立运行。

## 验证

Rust 回归涵盖并发启动 / 手动请求合并、启动失败后等待过期仍不自动重试、手动优先完成及被动缓存读取；菜单栏覆盖并行、断线、过期 / 未来时间、速度过期 / 零除、消息类型 / 已读与长模型名。

中英文浏览器 IPC 测试覆盖启动结果读取、不主动请求、手动按钮、下载 / 安装状态；将时间推进 25 小时并重开详情、运行界面时钟后，请求计数仍只有那一次手动点击。继续验证拖动、消息已读与浮窗菜单。此测试不代表原生菜单栏实机验收。

本机 Rust 1.98.0 workspace 测试 171 项通过，6 项显式联网测试按默认忽略；Clippy 无警告，Svelte 无错误 / 警告，15 项前端测试与发布清单测试通过。正式打包、原生安装、发布与本地清理结果在完成后补充。
