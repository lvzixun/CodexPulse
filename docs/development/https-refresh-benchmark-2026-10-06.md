# HTTPS 额度刷新与资源实测

日期：2026-10-06，Asia/Shanghai。最终产品路径为固定的 `GET https://chatgpt.com/backend-api/wham/usage`，TLS 验证开启，禁止认证重定向，失败不调用 CLI。CLI 仅保留在显式运行的历史基准测试中，不编入发布版。

## 本机真实读取

使用发布模式的显式 ignored 测试调用实际 HTTPS 适配器，包含凭据及 `.env` 加载、请求、解析和返回后的账号复核。Windows 和已运行 Ubuntu WSL 均使用对应来源的 Codex `.env` 代理，实际返回非空额度；没有改写认证文件、安装 CLI 或自动续期。

| 来源 | HTTPS 单次总耗时 | 历史 CLI 中位数 |
| --- | ---: | ---: |
| Windows | 1.178 s | 2.613 s（9 次） |
| WSL | 1.481 s | 3.496 s（3 次） |

HTTPS 每个来源只有 1 次计时样本，CLI 在更早时段测量，网络状态并未控制。不能据此声称固定加速倍数或 P95。发布桌面应用随后也实际读取两来源额度，界面显示已连接及 Codex `.env` 代理；自动刷新期间成功时间继续推进。历史 CLI 的详细阶段及 WSL PATH 诊断见 [对照报告](cli-refresh-benchmark-2026-10-06.md)。

## 前后资源采样

两次均采样 release 应用及其 Windows 后代进程约 125 秒，额度自动间隔 60 秒、产品窗口可见；旧版为详情总览，新版为设置页，因此不是完全相同的渲染负载。使用 CIM `Win32_Process` 的 PID / 父 PID、`PrivatePageCount` 和 CPU 时间；每次查询后休眠 100 ms，实际样本间隔约 0.29 秒。HTTPS 采样期间不编译、不运行额外 CLI 基准。

| 指标 | 改造前 CLI | 改造后 HTTPS |
| --- | ---: | ---: |
| 采样时长 | 125.275 s | 125.233 s |
| 样本数 | 432 | 427 |
| 观察到的进程总数 | 11 | 7 |
| 观察到的 Windows `codex.exe` 额度子进程 | 2 | 0 |
| 额度子进程私有提交内存峰值 | 35.45 MiB | 0（未启动） |
| 应用进程组私有提交内存峰值 | 280.23 MiB | 277.87 MiB |
| 可观察 CPU 时间增量总和 | 2.328 s | 9.797 s |

确定的改变是去除了额度查询的 CLI 子进程。进程组峰值差约 2.36 MiB；新版本 UI 与后台工作不同，不能把小幅差异归因于网络传输方式。HTTPS 样本的 CPU 增量反而较高，主要来自 WebView2 渲染进程，不能声称总体 CPU 降低。

`PrivatePageCount` 是私有提交内存，不是私有工作集，也不是 RSS；CPU 增量按每个观察到的进程首次与末次值相减，可能漏掉短进程首尾消耗。采样无法记录 Linux 进程内存，也可能漏掉极短 Windows 子进程。这里没有统一 UI 负载的 A/B 控制、参考硬件、8 小时漂移或设计预算 P95 验收结论。

自动采样期间，Windows / WSL 额度成功时间均推进到 16:43:03，本地 usage facts 从 11,824 增至 11,828，说明网络设置不阻断本地增量采集。

## 设置与账号验证

- 自动模式原生界面已验证额度 60 秒、消息 300 秒独立保存并生效。
- 单元测试验证手动模式无启动或定时任务、重复刷新合并、设置变化保留旧传输占位直到完成并忽略结果、两组独立调度、Retry-After 秒数及日期。
- 隔离文件测试在请求进行中替换模拟账号，验证即使旧请求成功也被丢弃；账号切换清除持久化的来源及聚合额度。没有切换用户真实账号。
- 持久化测试关闭并重开 SQLite，确认独立 61 秒 / 907 秒设置保留。原生界面输入额度 61 秒并失焦后即时保存，消息仍为 300 秒；两组改为手动并退出 / 重启，界面与 SQLite 都保留模式及间隔。
- 重启后观察 325.36 秒、65 次每 5 秒的本地只读抽样：Windows / WSL 请求时间、消息请求时间及 status / history / challenge 缓存时间全部不变，本地 usage facts 从 11,866 增至 11,886。结合手动调度测试，确认启动及超过两组已保存间隔后没有后台请求。本地账号探测继续运行，不发送 HTTP。
- 原生点击两组“立即刷新”：Windows 额度于 16:56:06 成功，消息 / 挑战于 16:56:08 成功；WSL 此次返回 `network_error`，保留同账号旧快照、显示失败并进入退避。此前 WSL 的真实成功读取已验证，不能将一次网络失败说成缺少 Codex。进程列表没有新增额度 CLI；实际失败处理不转用 CLI。按钮在排队 / 请求中禁用，调度测试验证重复请求合并。
- 验证结束通过原生设置将两组恢复为自动 300 秒，SQLite 只读复核一致；没有保存其他外观、隐私或来源草稿。

凭据和代理值不写入报告或产品数据库。忽略的 `work/` 保存脱敏计时及资源样本；报告仅汇总来源类型、错误码、资源数字和成功状态。

## 显式复跑 HTTPS 计时

普通测试不会联网。下述 ignored 测试读取现有 Codex 登录，仅将脱敏耗时与结果码写入忽略的 `work/`；不把认证材料作为命令参数。WSL 两项为可选，仅填写已经运行的真实发行版及来源 home。

```powershell
$env:PULSE_BENCH_REPORT = Join-Path (Get-Location) 'work/https-lifecycle.json'
$env:PULSE_BENCH_WSL_DISTRO = 'Ubuntu'
$env:PULSE_BENCH_WSL_HOME = '\\wsl.localhost\Ubuntu\home\your-user\.codex'
cargo test -p codexpulse --release measure_live_https_refresh -- --ignored --nocapture
```
