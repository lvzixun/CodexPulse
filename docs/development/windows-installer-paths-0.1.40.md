# Windows 安装目录恢复（0.1.40）

用户反馈 NSIS 安装到 `D:\Program Files\CodexPulse\codexpulse.exe` 时无法写入。安装模式为 `currentUser`，默认目录本应为 `%LOCALAPPDATA%\CodexPulse`，但初始化无条件恢复了注册表保存的旧路径。按反馈中的本机检查，旧目录已删除，父目录对普通用户仅开放读取，导致安装器无法重新创建并写入。企业安全软件是否参与阻断尚无证据。

## 修复

- 仅在应用及卸载程序均明确返回文件 / 路径不存在时，将注册表记录视为失效；读取被拒绝等其他错误保留原路径。
- 当前用户安装恢复失效路径时，用唯一临时文件检查创建目录及写入能力。不可写时沿用正常用户目录；仍可写的自选路径保留。现存安装及显式 `/D` 路径不自动迁移。
- 失效记录不再触发旧版本维护页；仍有应用但卸载程序丢失时允许覆盖修复。安装成功前不清理旧注册表记录，正常安装流程负责更新路径及卸载信息。
- 离开目录页、安装前置检查、旧版本卸载前及复制文件前均校验实际写入能力。静默 / 被动更新也受检查；不可写时返回错误码 2，并在交互安装中提示选择用户目录或手动修复现有安装权限。
- 检查不修改应用文件，清理临时文件及探测创建的空叶目录。创建多级新路径时，空的中间目录可能保留。目录可写不保证运行中、只读或被其他软件锁定的可执行文件可以替换。

## 验证方式

`scripts/test-windows-installer.ps1` 从生产模板中提取实际辅助函数，以发布构建使用的 NSIS 编译器编译并执行；只操作随机临时目录及 `HKCU\Software\CodexPulseInstallerTests\<随机标识>`。覆盖无旧安装、可写失效路径、受保护父目录、显式受保护路径、现存受保护安装、静默失败、卸载程序丢失、仅卸载程序残留、读取拒绝、中文及空格路径，并确认注册表 / 应用内容保留和临时文件清理。该检查已加入 Windows 发布 CI。

发布必须等待 Windows / macOS CI、两平台更新签名及最终资产校验通过。用户机器的实际安装交互和企业安全软件策略仍需独立验证，不能以 CI 替代。
