## 修正

- 最新状态和历史结果分开处理。最新状态成功就合并公告与缓存历史，历史超时 / 拒绝不将它丢弃或伪装成公告失败；设置单独展示历史失败，历史待更新时不将旧图表标为完整。
- 最新状态和挑战按用户设定间隔条件校验；HTTP max-age 是可复用缓存的期限，不是强制等待。历史沿用缓存 TTL，新公告出现 / 缓存到期 / 手动请求才重取；历史失败有自己的退避。
- 启动读取旧版部分成功缓存时重建公告列表，保留实际错误和原请求时间，不注入或伪造新数据。
- 客户端失败退避上限 15 分钟，但不短于用户设定间隔或服务端等待。手动模式不变，点击合并至少 30 秒；429 / Retry-After 和历史服务端等待不因手动请求绕过。
- 出现 CF-Mitigated: challenge 时显示站点要求访问验证，保留 Retry-After。不存储错误 HTML、任意响应头、账户或认证信息。
- 设置的“应用更新”显示编译版本、检查更新按钮与上次检查；保留 0.1.7 的匿名公开 GitHub 检查，不引入自动静默安装。
