# macOS 采集压力检查

2026-10-06，在当前未提交工作树运行 `pulse-core` 的 Release 采集基准（基线提交 `30466b5`）。硬件为 Mac16,8、12 逻辑核、48 GiB 内存，macOS 26.5.1 / 25F80；编译器为 Rust 1.98.0，原生 ARM64。测试只在自动清理的临时目录生成合成 JSONL 和 SQLite，不使用真实 Codex 日志、凭据或用户数据库。

## 可重复命令

```sh
cargo build --release -p pulse-core --example collector_benchmark
/usr/bin/time -l target/release/examples/collector_benchmark history
/usr/bin/time -l target/release/examples/collector_benchmark large 1024
/usr/bin/time -l target/release/examples/collector_benchmark large 64
```

本次原始数值保存在忽略的 `work/macos-collector-history.json`、`work/macos-collector-large-1024.json`、`work/macos-collector-large-64.json` 和同名 `.time` 文件中。独立进程顺序执行，没有并行争用；大文件生成后立即读取，不代表冷文件缓存。

## 一万条会话与双来源去重

合成 10,000 个文件，每个含 10 条累计 usage 记录，共 100,000 条事实、24,300,000 B 日志。首来源导入 9.702 秒，插入 100,000 条事实；镜像来源读取相同日志 1.719 秒，插入 0 条重复事实。最大单批耗时分别为 30.994 / 4.237 ms。

独立数据库汇总断言确认 10,000 个会话、120,000,000 tokens 和 80,000,000 缓存输入 tokens，缓存输入没有重复计入总量。随后对两个来源的 20,000 个文件执行未变化检查，耗时 0.135 秒，日志正文读取量为 0 B。最后追加 222 B，从已提交断点读取恰好 222 B，新增一条事实，耗时 0.380 ms；累计总量为 120,001,200。

整个独立基准进程的最大 RSS 为 12.813 MiB（13,434,880 B），峰值 physical footprint 为 6.969 MiB（7,307,648 B）。它包含合成文件生成、SQLite 和解析器，不是桌面应用进程组内存，也不证明产品补采前后的额外内存预算。

## 大文件与内存规模对照

重复写入有效、低于记录大小限制的约 128 KiB 消息正文，在正文前后分别写入 usage。两个尺寸都正确收集两条事实和 2,400 tokens，没有采集问题；未变化复读的正文读取量都为 0 B。

| 指标                            | 64 MiB 请求尺寸 | 1 GiB 请求尺寸 |
| ------------------------------- | --------------: | -------------: |
| 实际日志字节数                  |      67,166,869 |  1,073,872,885 |
| 采集耗时                        |         0.033 s |        0.561 s |
| 批次数                          |               9 |            130 |
| 最大单批读取                    |     8,388,608 B |    8,388,608 B |
| 最大单批耗时                    |        5.007 ms |      17.790 ms |
| 独立进程最大 RSS                |      10.516 MiB |     10.547 MiB |
| 独立进程峰值 physical footprint |       4.672 MiB |      4.704 MiB |

两次独立进程最大 RSS 相差 32 KiB，文件约增大 16 倍，没有按文件正文大小增长的迹象。每次读取断言不超过 8 MiB / 256 条记录，最终断点恰好等于文件末尾。批次边界可能切断正常记录，保留有限尾部并从最后完整记录重读：64 MiB / 1 GiB 的重读量分别为 991,686 / 15,997,622 B，计入上述读取量，没有伪装成磁盘只读一次。

## 证据范围

本次证明合成历史导入、双来源去重、未变化正文零读取、追加断点以及大正文分批读取的上述断言。它没有经过菜单栏 UI、完整目录监听调度或网络刷新，不能替代实际 App 的活动可见延迟、进程组 P95、GPU、冷缓存、Intel / 旧系统运行和长期资源验收。用户已要求不等待八小时，本轮未重启长期采样。
