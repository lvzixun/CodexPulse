# Windows 注册表访问

部分 Windows 环境中，应用直接写入当前用户的登录启动项会返回 `ERROR_ACCESS_DENIED (5)`，而系统 `reg.exe` 可以完成相同操作。已在本机用独立程序复现该差异，额外策略的具体来源尚未定位。

登录启动和透明效果偏好的注册表访问统一经过 `src/registry.rs`。安装器原有的 NSIS 注册流程保持不变。

## 实现

- 从 Windows 系统目录定位 `reg.exe`，以独立参数调用，隐藏控制台，不经过 shell 或 PATH 查找。
- 读取使用自动清理的临时目录和 UTF-16LE 导出，避免控制台代码页损失路径字符；解析只取请求键的值，不合并子键。
- 保留字符串、展开字符串、DWORD 和二进制类型，区分值不存在与执行失败。
- 写入、删除后读取真实启动项，保留归属检查和重复关闭的幂等性；真实 `StartupApproved` 始终只读。
- 登录项操作在后台执行并串行处理，避免阻塞界面或让状态刷新与切换交错。

## 验证

导出解析器使用真实 `reg.exe export` 生成的合成样本，覆盖中文、emoji、空格、引号、多行字符串、DWORD、展开字符串和多行二进制，以及子键隔离和损坏数据拒绝。

Windows 测试使用隔离的 `HKCU\Software\CodexPulse*Tests` 键，覆盖类型往返、缺失键、启动项开关、移动后的可执行路径、未知审批状态及审批记录只读行为。纯解析器可在 WSL 独立运行；Windows 的测试编译链接与实际执行应分别记录，不能用 `--no-run` 结果代替测试通过。

发布复核发现 Windows 时钟读数可能重复，单靠进程号和时间戳不能保证并行测试的注册表键唯一。两个测试 fixture 均增加原子计数器；在临时测试工程固定时钟后，修改前 5 项测试因共享键失败，修改后全部 8 项通过。该复核仅修改临时工程的时钟读数，仓库中的测试仍使用真实时钟。
