# 0.1.19 正常等待状态与实时速度

## 修复

0.1.18 菜单栏把除 connected / verifying_account 外的账户状态都判为异常。本机记录实际为 awaiting_refresh、失败次数为 0，因此正常等待也显示了 `!`。判定现与设置页保持一致：空状态、ready、connected、verifying_account、awaiting_refresh 均不报警；认证过期、请求失败及账本查询错误仍提示异常。不会为了消除标记而发出账户请求。

## 实时发布

速度来自本地 JSONL 的 token_count，计算仍为本轮累计输出 tokens ÷ 已观测轮次时间；完成时采用日志中的有效 duration_ms。包含推理、工具和等待，不改为推测的流式瞬时速度。

文件通知现在立即唤醒现有采集器，同一批路径只产生一次唤醒；满消息队列不丢缓存路径，路径缓冲仍最多 4096。已有读取、游标、去重和定期修复继续工作，没有新增目录轮询或线程。

实时发布节流从一秒降至 250 ms，只在读取新的完整日志记录后处理。轻量查询仅取已展示会话的 metadata，更新活动、模型和速度；保留标题索引解析后的名称、项目、会话数量、tokens / 费用及账户状态。30 天统计和完整 snapshot 仍按原来一秒节流刷新，避免四倍执行聚合查询。macOS 收到实时变更后立即更新原生文字，仍合并相同内容的写入；隐藏面板只更新宿主缓存与菜单栏。

前端可见时每秒更新本地显示时钟，使过期样本及时显示 `—`；系统语言检查维持每分钟，隐藏时清理两组界面计时器。没有新 token_count 样本就不产生新速度值。账户、Resets 与应用更新的网络调度保持原样，WSL 既有采集周期不变。

## 验证

回归覆盖正常状态不报警、真实认证 / 网络错误仍报警、恢复为等待后清除标记；文件事件合并 / 满队列 / 缓冲上限；实时 metadata 不覆盖名称、统计和网络状态；不完整 JSON 行不产生新速度样本、提交完整行后更新、反复读取 metadata 不重复计费。

本机 Rust 176 项测试通过，6 项显式联网测试默认忽略；Clippy 无警告，Svelte 无错误 / 警告，15 项前端测试和发布清单测试通过。当前本机数据库只读 metadata 查询及 JSON 解析，10 个会话、40 次采样的 P95 为 0.035 ms；此测量不包含文件事件、采集调度或原生绘制，不作为端到端延迟证明。
