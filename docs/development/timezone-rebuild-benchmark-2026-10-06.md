# 时区重建验证与基准

2026-10-06，Windows 本机 release 存储基准，32 逻辑处理器。使用隔离的临时 SQLite，10,000 sessions、100,000 facts、3 个模型；数据是合成计数，不读取用户日志或凭据。

## 方法和结果

在已有查询基准后，将每日汇总从 Asia/Shanghai 重建为 UTC。每批 256 条，rowid 游标读取账本的规范化列，临时 STRICT 表累加；每 64 批读取旧时区 30 天汇总并断言有效，完成后原子提交新的桶与设置，复核总量、输入 / 缓存 / 输出、session 数和 100k facts 未变化。

| 指标 | 本次结果 |
| --- | ---: |
| 重建总时间（包含穿插的旧查询） | 476.41 ms |
| 批次数（含最终空批） | 392 |
| 每批中位数 | 0.306 ms |
| 每批 P95 | 0.379 ms |
| 每批最大值 | 1.173 ms |
| 最终原子提交 | 0.126 ms |
| 穿插旧汇总查询最大值 | 59.06 ms |

这是一轮存储层重建，不包含桌面调度的让出时间、UI 事件、日志采集及 WebView 渲染。392 批的 P95 是批次分布，不是多轮总重建 P95。桌面应用每轮约 8 ms 重建预算，单批执行期间不抢占，活跃重建时消息等待改为 10 ms，继续处理采集和设置；重建前后的普通后台等待为 300 ms。单批最多 256 条，不持有跨批事务。

汇总只保留当前已发布时区，反复切换不累积过期桶。临时表随连接退出自动清理；取消和失败保留旧设置 / 汇总。最终提交时间仍受日期 / 模型桶数量影响，本次只有 3 个模型和 30 天，不能代表极端多年、多模型数据或慢磁盘。尚未据此声明整个产品达到 CPU / 私有工作集预算。

## 自动验证

新增六项测试：新汇总与独立重新构建账本一致；重建期间追加和 ready 后追加均纳入且不重复；取消 / 重启保留旧统计与断点；设置提交故障同时回滚桶并可重试；新时区合并桶溢出回滚整批；纽约春秋 DST、圣保罗午夜缺口、Apia 跳过日期的范围查询；批次上限与重建期间查询旧结果。

测试不修改真实 Codex 文件，重建不更改 facts、session 汇总、历史价格、标题或采集断点。另新增两项桌面测试覆盖自动检测时的任务替换 / 回到已发布时区取消，以及启动持久化 / 重启保留有效时区及两组刷新配置。完整 Rust 测试目前 92 项通过，另有 2 项联网基准默认忽略。前端检查与 clippy 通过。

## 原生验证

最终产品自动跟随系统时区，不提供选择、应用或取消按钮。系统时区启动时及每 60 秒检测，自动替换过期任务；读取失败或重建失败保留有效结果并稍后重试。系统变化触发使用隔离测试注入检测结果验证，未修改 Windows 时区。

真实产品账本已完成 UTC / Shanghai 重建一致性验证：11,949 条记录、150 个 UTC 日期 / 模型桶的总量、输入 / 缓存 / 输出、已计价费用、未计价 tokens 及不完整事件数全部与独立 Python 聚合相符；退出并重启后的 11,953 条记录也全部吻合。恢复 Asia/Shanghai 后，11,964 条记录、154 个日期 / 模型桶再次与独立计算一致。每次仅保留已发布时区的桶，195 个采集断点与两组自动 300 秒刷新设置保留。没有改动用户 Codex 文件，也没有人为损坏真实产品库；故障回滚由隔离测试覆盖。

系统时区及本地数据隐私说明已从设置页删除，时区检测和自动重建仍在后台运行。重启后的 12,007 条事实、154 个日期 / 模型桶与独立聚合全部吻合。简化刷新设置显示额度手动、消息每 5 分钟，两个值重启保留；随后恢复两组自动 300 秒，12,018 条事实再次复核一致，采集断点仍为 195 个。
