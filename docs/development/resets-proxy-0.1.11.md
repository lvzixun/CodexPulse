# 0.1.11 Resets 与 Codex 代理对齐

## 问题与实现

本机 GUI 请求的 403 已通过独立 GUI 探针定位为企业域名策略拒绝；终端请求同机返回 200，两种 TLS 在 GUI 均受限制，因此没有用改 TLS 掩盖问题。用户按流程允许公开域名后，0.1.8 原生手动刷新已成功同步公告、历史及挑战。更新检查的另一个 403 是 GitHub 匿名 API 配额耗尽，继续遵守等待。

按用户后续要求，公开 Resets 请求复用首个已启用、可用 Codex 来源的 `.env` 代理配置。源目录仍按原设置及 CODEX_HOME 探测；后台同步已发现的活动来源，排除不可用 / 停止的 WSL，不新增发行版启动或日志轮询。读取仅涉及有界 `.env`，不依赖登录状态、不读取 auth.json；代理凭据只用于连接代理，公开站点请求不携带 OpenAI 账户认证。代理配置不写入日志、数据库、IPC 或发布报告。

沿用 HTTPS_PROXY → ALL_PROXY → HTTP_PROXY、大写 / 小写及本机进程变量备用的既有规则，NO_PROXY 使用公开目标 codex-resets.com，账户请求的 chatgpt.com 规则不变。无配置保持现有直连 / 进程代理；无效配置报错并保留公告缓存。每次请求重读 `.env`，不中途切换路由或绕过服务端等待。公告、历史、挑战及按需译文都使用相同代理选择。

版本也合入远端已有的标题栏拖动及旧 WebView 选中标签修正。发布产物与原生验收完成后补充；不发布企业错误原文、出口 IP、报备信息或真实用户数据。
