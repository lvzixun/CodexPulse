# 模型分页验证与查询基准：2026-10-06

模型分类现通过独立 IPC 每页返回最多 20 条；周期用量 snapshot 不再携带全部模型数组。总计、独立 session 数、模型数和 30 个日期桶继续单独查询。分类按总 tokens 降序、模型名升序；首次捕获不可变账本 rowid 上限，翻页期间的追加不会改变已有页的排序及成员。后续页出现新事实时提示刷新；日期范围或系统时区改变后重置游标。整数游标以十进制字符串传输。

模型页只聚合规范化计数字段，不解码事实 JSON、不执行每模型 session 查询。SQLite 仍需聚合当前日期范围内的事实；每页返回有界不代表数据库扫描成本恒定。schema 5 添加 `facts_time_model_counts` 覆盖索引，没有改写历史事实、设置或采集断点。旧 schema 4 升级、重复打开、未来版本拒绝与查询计划都有测试。

## Release 存储层测量

PowerShell 中运行：

```powershell
$env:PULSE_BENCH_MODELS = '263'
cargo run --release -p pulse-core --example benchmark
Remove-Item Env:PULSE_BENCH_MODELS
```

程序生成隔离临时数据库，不使用用户账本。10,000 个 sessions、100,000 条唯一事实、263 个模型、30 个自然日，1,000 条一批写入；每项预热 5 次后测量 100 次。本机 Windows、32 个逻辑处理器；不代表设计参考硬件或冷态结果。两次生成时间为 2026-10-06 09:30:44 UTC 和 09:32:02 UTC，对比同一新增分页查询加入覆盖索引前后，不能作为整个旧产品与新产品的资源占用对照。

| 测量项 | 覆盖索引前 | schema 5 覆盖索引后 |
| --- | ---: | ---: |
| 模型首屏查询 P50 | 301.58 ms | 73.05 ms |
| 模型首屏查询 P95 | 317.15 ms | 75.66 ms |
| 模型首屏查询最大值 | 332.97 ms | 82.34 ms |

索引以约 10.16 MB 的主库增量和约 3.72 秒的导入增量换取分页查询改善。导入包含合成事实写入与聚合，不是 JSONL 采集基准。首屏 20 条序列化为 5,883 B；独立总计含 30 个日期桶为 2,687 B。完整遍历 14 页到达 263 个分类，120,000,000 tokens 与独立总计相等。

263 个模型负载的时区重建总耗时 408.73 ms，256 条批次 P95 0.737 ms，最终发布 17.10 ms。最终原子发布成本会随分类桶数增长，不由批次时间预算抢占；旧报告 3 个模型的发布时间不能推广到此负载。

以上测量是存储层暖态延迟，不包含原生 IPC、画面呈现、进程组 CPU / 私有工作集 P95、参考硬件或 8 小时漂移，完整性能验收仍未完成。
