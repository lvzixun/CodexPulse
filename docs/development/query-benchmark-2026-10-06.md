# 本地查询基准：2026-10-06

命令：`cargo run --release -p pulse-core --example benchmark`。

固定工作负载为 10,000 个独立 sessions、100,000 条唯一 usage facts、3 个模型和 30 个自然日。以 1,000 条记录为批次写入隔离的临时 SQLite 数据库；每项查询预热 5 次，测量 100 次。程序先验证独立 session 数、总 tokens、缓存输入不重复计数及 30 个日期桶。

本机为 Windows 11 专业版（10.0.26300），32 个逻辑处理器，可见物理内存 68,463,702,016 B（约 63.76 GiB）。这不是设计中 8 核 / 16 GB 参考配置上的正式验收，也不涵盖原生界面、JSONL 解析、WSL 或 8 小时常驻。

基线生成时间为 `2026-10-06T06:28:03Z`，优化后为 `2026-10-06T06:28:52Z`。原始实现对每个模型的独立 session 计数访问了 facts 的数据页；migration 002 为 model/time/session 和 time/session 提供覆盖索引，并为 source/session 反向查询提供索引。30 天总览仍实际执行独立 session 计数，没有去掉这项统计。

本次改善以约 10.7 MB 的主数据库增量和约 0.9 秒的导入增量换取查询延迟降低。本机查询 P95 达到 100 ms 目标；其他性能和参考硬件要求仍待验收。测量时同时运行开发版桌面应用，优化测量还伴随正常后台活动，因此结果不是无负载理想值。

补充 schema 3、session 分页 / 详情及未知计数后的复测（`2026-10-06T07:43:32Z`）：30 天总览 P50 58.84 ms、P95 62.73 ms、最大 72.53 ms；最近 10 个 sessions P50 0.25 ms、P95 0.32 ms、最大 0.41 ms。session 首屏游标页 P95 0.31 ms，单项完整详情 P95 0.19 ms（本负载每个 session 10 条 facts；不能代表超长 session）。导入 7.02 s，数据库 86,712,320 B。整数溢出触发器、时间规范化和计数完整性检查增加导入工作；查询仍在本机目标内。
